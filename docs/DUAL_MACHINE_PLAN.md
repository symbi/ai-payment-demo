## 首条开发路径与接口不变量

1. 复用卖方 exact 报价与现有报告资源，后端保存 Grant；页面只提交许可设置或对象引用，不能自行声明已获准。
2. RiskEvidence 保留原始分数、受限标签、来源模式和时间来源。FIELD_MAP 逐条记录确认依据；观察到 0—100 的几个样本不足以确认量纲。
3. Decision 的四动作与 FinalGate、Operation 独立：ALLOW 不代表已签名；ALLOW_WITH_LIMIT 不代表已限额付款。
4. 原报价高于 cap 时必须停止或取得卖方新报价；不单边改价、不拆单绕过 cap。低于 cap 时只付原报价金额。
5. 已有未决/完成操作优先查询原记录，不新扫、不新签；输入/Grant/policy 改变使未签旧决定失效。旧签名不能靠改页面宣称撤销。
6. 首次购买历史为零可以如实显示；余额未知与风险未知分别解释，不伪造历史、余额或允许结果。

## 双 Symphony 的领取与资源边界

本轮只发布交接文档，不创建 Issue 批次。后续沿用 J0—J5、既有负责人及可复用 Issue。总目标只汇总，不被执行器领取。

每个可执行任务必须固定：Issue、baseCommit、contractRevision、ownerMachine、写入范围、验收命令、依赖及允许的网络活动。本轮建议机器标签 `machine:company-offline` / `machine:private-validation`，再配合本轮 ready 标签。每台机器只监听自己范围，显式拒绝同时带两个机器标签、缺 owner 或不在批准清单中的任务。

首轮每台最多 1 个 worker，合计最多 2，不叠加 sub-agent。若两个离线任务确实适合在公司电脑并行，必须先暂停私人机器领取并明确重新分配这两个名额，不能默认每台各开 2 个。

本机一次性启动锁只能防本机重复，不能称为跨机锁。用互斥任务清单和单一主控交接防止重复；转移 owner 前停止旧执行、保留产物、确认不再领取，再开放另一侧。完成移到待验收并移除 ready；阻塞不无限重跑。

模型由主控按任务复杂度选择并记录实际模型：资料整理用已验证可调用的低成本档；页面与常规接口用中档；最终签名、持久预算、并发恢复用高能力档。模型可用性以各机 Codex CLI 为准，不照搬桌面模型名，不默默回退。

迁移只包含已用到的 Symphony 源码版本/补丁、GitHub 适配、工作流、模型分配及启动保护的必要文件，去除绝对路径。禁止复制 token、缓存、历史 attempt 状态或 wallet 配置。当前启动器会移除风险 API key，私人侧需要独立受限扫描入口，不能直接扩大所有 worker 的环境权限。

私人电脑无需安装 Self Learning 或 Work Map；本计划是该规划技能的输出，不是需要在每个 worker 中运行的依赖。执行所需步骤直接写入 `PRIVATE_MAC_SYMPHONY_PROMPT.md`，其工具清单区分项目依赖、Symphony 配置和可选浏览器能力。未来新增必需 Skill 必须在相应交接中明确来源/版本、用途及权限，不能默默要求私人机器拥有公司技能库。

运行时限、模型尝试上限和 API 请求上限在每张获准任务中明确记录。先复用现有停止机制；本轮不虚构配置参数，不另建分布式调度平台。
